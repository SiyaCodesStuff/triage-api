# Security controls

- Authentication uses Argon2id passwords and signed, expiring access JWTs. Every protected request looks up the current user id/role in PostgreSQL; deleted users receive 401 and role changes apply immediately. See [auth documentation](docs/auth.md).
- Refresh tokens are stored only as SHA-256 hashes. Rotation revokes the old session; reuse revokes all refresh sessions for the user. Existing access JWTs remain usable until expiry if the account still exists. Logout clears cookies and revokes the presented refresh session.
- Cookies are HttpOnly, Secure in production and SameSite=Strict. Every unsafe `/api/v1` request requires `X-CSRF-Protection: 1`. Browser preflights are restricted to explicit, fully trusted HTTP(S) origins in `CORS_ORIGINS`. CORS is disabled when unset; wildcard origins are rejected, including in production. CORS governs browser access and is not an authentication mechanism.
- Login, register and refresh share a budget of **10 attempts per 15 minutes per IP**, including successes and validation failures. Excess requests receive 429 with `{ "error": { "code": "RATE_LIMITED", "message": "..." } }` and retry headers. A general 300/minute limiter also applies; health/readiness are outside it. Rate-limit state is in memory per process and resets on restart; multiple replicas require a shared store or an upstream limiter. Configure `TRUST_PROXY` only for the exact number of trusted proxy hops, and prevent clients from bypassing that proxy.
- JSON parsing remains strict with a **16 KB** body limit. Oversized bodies receive 413 `PAYLOAD_TOO_LARGE`; malformed JSON receives 400 `INVALID_JSON`. Zod validates inputs, SQL parameters are bound, and schema constraints enforce database invariants. USER ticket visibility, staff privileges, authorship and status transitions are enforced server-side.
- Helmet applies security headers and strict CSP globally. Inline scripts/styles are allowed only under `/docs` for Swagger UI. `ENABLE_DOCS=true|false` controls both `/docs` (including assets) and `/openapi.json`; it defaults to false in production and true otherwise. Explicitly enabling docs in production makes the specification/UI public.
- Errors use the standard envelope. Unexpected errors return a generic 500 without internal messages or stack traces, including in production. Unhandled-error logs include only the error name and request method/path, not raw error objects that may embed credentials. HTTP logs omit bodies, cookies, authorization headers and query strings; public user responses omit password hashes and credentials.
- Seed credentials are required only by `db:seed`; passwords are hashed and existing admins are preserved. Production seeding requires `--allow-production`. See the [README](README.md).

Deployment deliberately requires production HTTPS, strong distinct JWT secrets, restricted database access and careful origin/proxy configuration. Dependencies should be kept updated. The application does not provide a distributed rate-limit store or access-token logout blacklist.
